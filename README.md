# PEAK Zombie Director

PEAK / BepInEx 的房主导演附加 Mod，依赖 **tony4twenty PEAK Zombies 2.0.0**。这是尚待实机验收的 **0.1.5 实验版本**；已针对实际程序集构建，不包含伪造的游戏 API。构建和模拟测试不代表游戏、多人与 UI 验收通过。

## 安装和使用

1. 通过 Thunderstore 安装 `BepInExPack_PEAK 5.4.75301`、`tony4twenty-PEAK_Zombies-2.0.0`。为确保配置和伤害一致，所有玩家安装相同版本的依赖与本插件。
2. 将发布压缩包中的 `BepInEx` 目录合并到游戏根目录，确保同一插件目录下同时有 `PEAKZombieDirector.dll` 和 `PeakZombieDirector.Core.dll`。
3. 启动游戏，按 **Ctrl+F8** 打开设置；可在总览页修改快捷键。大厅与攀登过程均可打开面板。
4. 选择 Easy / Normal / Advanced / Expert / Custom，编辑任何玩法参数会转为 Custom。每次编辑自动保存活动配置；“保存当前配置为 Custom”更新单独的 Custom 存档。切换其他预设不会覆盖已保存的 Custom。
5. 房主可编辑玩法，客户端显示房主快照，只能编辑自己的语言与快捷键。快照每两秒同步；中途加入者等待下一次快照。

配置文件：`BepInEx/config/PEAKZombieDirector.cfg`。设置修改在下一次导演更新生效；生命周期变更沿用僵尸原始出生时间，因此缩短寿命可能让现有僵尸立即过期。配置文件的非法范围、NaN 与枚举在启动时修正并记录警告；外部修改文件后重启游戏。

## 已实现的功能

- 初始数量、定时波次、时间增长、数量上限增长、随机数量/间隔波动、0 上限表示无限。
- 每波预算、每秒网络生成预算、位置搜索预算和每轮替换预算；大波次分散到后续更新，不在一帧无限生成。
- 复用原版僵尸的网络生成与 AI；持续锁定有效玩家、最近/随机/优先原目标，目标死亡或离开后重选。
- 三维/水平距离、持续超距检测、卡住检测、冷却替换；先验证位置和生成，再删除旧僵尸。删除失败回滚新僵尸，回滚失败时暂停新增并重试清理。
- 优先遮挡与身后位置、避免正前方、可选视线内回退。地面、坡度、碰撞、玩家间距、有限坐标和场景加载检查始终执行；找不到位置则保留旧僵尸。
- 行走/奔跑/攀爬/跳跃/扑击速度、咬击初始伤害、扑击恢复间隔、感知距离、扑击触发范围、寿命与远距离清理配置。
- 可选择使用原版地图生成点，由导演通过公开 `SpawnAt` 接管，遵守同一数量与网络预算，每个点每阶段最多使用一次。依赖 Mod 的地图散布器与定时波次始终暂停，避免双重控制。
- 默认在全部已加载生态区工作；可切换为仅 Roots。
- 独立游戏内 IMGUI 面板：分类导航、滚动、数字滑块和输入框、枚举下拉、开关、中英切换、快捷键、状态和诊断。阻止玩家输入并管理光标。
- 只有 Photon 房主执行生成、删除、波次和目标操作。版本不符、异常和房主变更会停止调度。房主变更后等待场景变化/新局初始化，不冒险迁移旧导演。

## 构建

安装 .NET SDK 8.0.427。运行目标为 Unity Mono 的 `netstandard2.1`，测试目标为 `net8.0`。

```bash
export PEAK_MANAGED_DIR='/path/to/PEAK/PEAK_Data/Managed'
export PEAK_MOD_REFERENCE_DIR='/path/to/reference-mods'
# reference-mods 包含 BepInEx.dll、0Harmony.dll、Zombies Anywhere.dll
bash scripts/build.sh
bash scripts/test.sh
python3 scripts/package.py
```

输出：`src/PeakZombieDirector.Plugin/bin/Release/netstandard2.1/PEAKZombieDirector.dll`，另需同目录的核心 DLL。安装压缩包：`artifacts/PEAK_Zombie_Director-0.1.5.zip`。

云环境可运行 `bash scripts/setup-cloud.sh`。脚本只在仓库外准备工具和参考 DLL，以固定版本、TLS 和校验和下载公开资源，不会把游戏 DLL 或依赖 Mod DLL 打进发布包。云环境参考 DLL 来自 ShootZombies 固定提交，属于编译兼容性证据；最终发布前须用自己当前安装的合法游戏程序集重新构建并实测。

## 当前限制与验收要求

- 没有启动真实 PEAK/Unity 环境；实际地形合法性、追击效果、中文字体、常见分辨率、光标恢复和多人行为均**未实机验证**。详见 [实机验收](docs/VALIDATION.md)。
- 使用独立 IMGUI 面板，没有集成 PEAKLib 原生控件或 ModConfig 原生设置页，也未验证原生视觉一致性。
- “伤害倍率”仅作用于已经核实的初始咬击 injury/spores；“攻击间隔倍率”是扑击恢复时间；“攻击范围”是扑击触发范围。没有把未经核实的完整攻击系统包装成假选项。
- 寿命禁用只禁用老死；**没有独立的“忽略所有自然死亡”功能**。危险物与战斗仍可杀死僵尸。没有禁用地面/碰撞安全验证的开关。
- 地图生成选项复用原始地图点，不重新启用依赖 Mod 的生态区散布器。每个地图点在本阶段只消费一次，切场景后重置。
- 移动倍率等依赖配置是 PEAK Zombies 的全局 NPC 设置，会影响房间其他来源的 NPC。导演仅替换/删除自己生成的对象；总存活上限包含其他来源僵尸。接管时暂存依赖配置，正常退出时恢复；依赖菜单主动保存或崩溃后的持久化行为仍需实测。
- 替换时可能临时多一只僵尸。若网络删除与回滚都失败，暂停新增直到清理成功，不能保证网络故障期间数量瞬时严格相等。
- 房主迁移不转移所有对象/计时状态；安全停止并暂停依赖生成，等待场景变化或新局。没有在本环境验证离线游玩、原版客户端或其他僵尸 Mod 兼容性。

API 证据、依赖来源、版本与许可证说明见 [依赖研究](docs/DEPENDENCIES.md)。参数完整清单见 [配置参考](docs/CONFIGURATION.md)。本仓库代码使用 MIT 许可证，不授予第三方游戏与 Mod 程序集的再分发权。

## 0.1.1 修正

- 位置查询改用角色物理 `Character.Center`（视线起点用 `Head`），修复根节点静止导致的距离/卡住误判与生成位置偏移。
- 面板输入拦截仅限本地非僵尸玩家，避免影响 AI 输入。
- 每次导演更新续锁目标；先唤醒再设置目标，避免依赖的 SnapChase 覆盖导演锁定时长。
- 增加超距/卡住替换分类日志，以及对象外部销毁/进入 Dead 状态与存活时间的警告，帮助定位短时间成批消失。
- 用户报告的实际扑击和死亡行为仍需日志与复测确认；本次未将修改宣称为已实机验证。

## 0.1.2 扑击与命中调整

默认扑击触发范围从 10m 改为 3m，扑击恢复间隔倍率从 1 改为 0.15（原型恢复 5s 时为 0.75s）。新增扑击落地倒地时间 0.75s、命中后僵尸倒地时间 0.75s、同一僵尸咬击冷却 1.5s；这三个值通过已核实的 PEAK Zombies Combat 配置控制。落地倒地与起身恢复仍是两个独立阶段。

新增明确的咬击初始受伤 10%、孢子 5%，再乘伤害倍率并限制每项最大为 100%，不再依赖预制体初始伤害是否为零。沿用真实碰撞触发器，不提供空扑时自动范围扣血；孢子后续效果仍由原版负责。实际命中本地玩家时记录 `Bite contact confirmed`，可区分没碰到和已走伤害流程，但日志本身不证明最终状态被其他 Mod/游戏模式保留。

**已有配置保留原值。** 升级后请把“扑击触发范围”改为 **3**、“扑击恢复间隔倍率”改为 **0.15**；也可重新选择预设加载新默认值（会重置当前活动参数，先保存 Custom）。新加入的参数缺失时自动使用以上默认值。多人所有人须升级到相同版本。当前没有实机确认伤害/命中效果。

## 0.1.3 设置界面重设计

深色面板与青绿色重点色、统一字号/间距、圆角导航与参数卡片；总览使用存活/波次/倒计时卡片，难度使用独立预设卡片。参数页支持按中文名称或英文键搜索，数字输入与滑块并存，枚举显示中英文可读名称，保存反馈短暂显示。面板按屏幕尺寸缩放并限制超大屏放大比例；布局、字体与点击效果仍待真实游戏验证。关闭与销毁时恢复光标，主题纹理与皮肤随插件销毁释放。

升级只需退出游戏并替换两个 DLL；保留已有配置。0.1.3 不更改玩法参数与用户配置。

## 0.1.4 起跳门限与持续接触

对本导演管理的僵尸，在原版 TryLunge 和 StartLunging 入口重新读取双方物理中心，距离不得超过 min(AttackRange, LungeContactRange)，高度差不得超过 LungeHeightLimit；不依赖距离缓存。新增近身起跳上限默认 2m、高度差默认 1.5m，即使旧配置 AttackRange=10 仍受新上限约束。两项可在属性页调整。仍由游戏决定冲刺、地面、视线等其他条件，不重写移动或给僵尸瞬移/强推力。

在原有咬击触发器对象上加入持续重叠回调，仅当物理触发器实际与本地玩家重叠、处于 Lunging 且原咬击冷却已结束时，再调用同一个原生 OnTriggerEnter（含 PEAK Zombies 补丁）。它复用同一个 lastBitLocalCharacter 时间戳，绝不另写伤害路径或对远处玩家范围扣血。回调异常会禁用该转发组件并写错误。

启动记录 Combat settings；成功起跳记录 Lunge started 与实际物理距离（最多每 5 秒一条）；原生流程走到命中回调记录 Bite contact confirmed。这能辅助区分起跳、接触与伤害流程，不证明最终伤害已实机生效。**持续空扑/无伤害尚未在真实游戏中验证解决。** 升级替换两个 DLL，所有联机玩家同版本。若仍有问题，请提供本版本复现后的 LogOutput.log 和 PEAKZombieDirector.cfg，保留现有配置不要先删档。

## 0.1.5 咬击伤害 API 兼容修复

用户的 0.1.4 实机日志确认：伤害配置非零、起跳距离正常，但 PEAK Zombies 2.0 的 BiteColliderPatch.Prefix 引用不存在的六参数 CharacterAfflictions.AddStatus，导致 MissingMethodException。编译参考游戏提供的是五参数 AddStatus，不能靠调整伤害倍率修复此问题。

0.1.5 在启动时检测实际加载游戏是否提供旧六参数 API。缺失时，仅解除依赖 `tony4twenty.ZombiesAnywhere.Patches` 中精确的 BiteColliderPatch.Prefix，恢复**游戏原生咬击回调**；保留其他 Mod 与该依赖的所有其他补丁，不修改任何 DLL。原生伤害调用会使用游戏自己的兼容签名。额外的精确 IL 适配只把已核实的 5 秒咬击冷却常量替换为导演冷却读取，不复制或另行实现伤害。找不到指定补丁不会盲目移除其他补丁；若原生 IL 结构变化会明确报错。插件退出时恢复原补丁。

兼容模式在日志记录 `Bite compatibility enabled`。游戏仍提供六参数旧 API 时不启用这个兼容模式。伤害数值、已有配置和 2 米近身起跳限制均保留。根因已由用户日志确认；修复版尚待实机验收，自动化测试不能证明实际扣血。所有联机玩家需更新两个 DLL。
