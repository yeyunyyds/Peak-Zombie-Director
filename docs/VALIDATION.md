# 验证范围与实机验收

## 云环境证据

- 真实参考程序集编译：.NET SDK 8.0.427，netstandard2.1，依赖为 PEAK Zombies 2.0.0、实际 Assembly-CSharp/Unity/Photon/BepInEx/Harmony DLL。
- 自动化 xUnit 模拟测试覆盖预设、Custom 隔离保存、编解码修正、时间增长、cap、网络预算、距离持续条件、卡住、替换成功/失败/删除回滚、无玩家、房主权限、快照验证和重置。测试结果记录于运行生成的 `tests/PeakZombieDirector.Tests/TestResults/core.trx`。
- 模拟 API 没有冒充游戏 DLL；只有 Core 测试使用 FakeWorld。插件编译引用实际 DLL，没有空游戏 API 替身。
- 没有 PEAK 可执行文件/Steam 游戏安装，未启动 Unity，不提供或宣称游戏预览。

## 发布前必须执行的实机步骤（均未执行）

1. 用当前合法游戏安装的 Managed DLL 构建；安装 BepInEx、PEAK Zombies 2.0.0 和本插件全部两个 DLL。观察无依赖加载与 Harmony 错误。
2. 在大厅及进入地图后打开 Ctrl+F8，测试 1280×720、1920×1080、2560×1440：中文字体、滚动、下拉、输入框、缩放、滑块和点击。打开时操作不会移动/攻击，关闭后原光标和输入正常；同时有其他菜单时不得破坏其光标状态。
3. 逐个选择四档预设并查看完整参数；修改任意玩法值变 Custom。保存 Custom，换预设再回 Custom，重启游戏再次确认。测试当前预设重置与 Custom 重置 Normal，确认未保存提示正确。
4. 设置首次延迟 1s、波次 2、间隔 10s、cap 5。确认初始/波次数量、上限暂停、增长周期和随机波动；打开高数量警告，观察每秒生成不超过预算。
5. 只开地图点、关波次，靠近原始地图点，确认最多消费一次，且不与依赖或原版再生成。分别测试所有生态区/Roots 开关及场景卸载。
6. 放大奔跑倍率，检查追击速度；分别检查攀爬、跳跃、扑击、初始咬伤/孢子与恢复时间。寿命开关不等于免疫战斗死亡。
7. 设置 cap 已满，拉开距离，确认先出现替代再消灭旧僵尸，最终数量不变；失败位置、悬崖、墙体、无支撑/未加载区域不应生成到原点。
8. 验证视线外/身后偏好、正前方避免、视线内回退开关。在高低差地形比较三维/水平模式。让僵尸卡住，测试替换与冷却，无同轮递归。
9. 双客户端同版本联机，只有房主生成/删除。客户端看到房主参数和倒计时但不能编辑玩法，语言与快捷键独立。确认客户端受到的咬伤参数一致。
10. 客户端中途加入、退出、目标死亡和全灭；无目标停止新增；更换目标而不追已离线玩家。检查角色 PhotonView/位置匹配。
11. 房主离开后，确认新房主导演停止，依赖自动生成暂停，UI 提示等待新场景/新局。开始新局验证无重复导演、旧计时器或长期残留对象。此版本不保证旧房间继续无缝迁移。
12. 测试场景切换、退出房间、插件禁用与关游戏；确认自己的僵尸被清理，依赖配置恢复。依赖菜单主动保存、崩溃与错误退出的配置恢复需要单独检查。
13. 移除或替换依赖版本，确认有明确加载/版本错误，不继续冒险生成。不同插件版本客户端应显示不兼容而非接受快照。
14. 逐步提高数量，观察 CPU、物理和网络。搜索和替换预算不等于无限僵尸的性能保证。

## 尚未提供的功能/保证

- PEAKLib/ModConfig 原生设置页面集成和原生视觉一致性。
- 单独的全自然死亡免疫开关、关闭生成安全校验的开关。
- 重开 PEAK Zombies 自带生态区地图散布器；地图选项由导演复用现成点。
- 无缝房主迁移、原版客户端兼容保证、实机多人验收。
- 跨同一场景的每段篝火计时持久化；当前“阶段时间”以可玩场景初始化为起点。所有玩家无效时不累计待生成波次。
